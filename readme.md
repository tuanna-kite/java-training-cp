## 🔍 My Problem-Solving Process

For non-trivial problems, I try to reason through the following pipeline:

```text
Requirements
    ↓
Constraints
    ↓
Mathematical / Computational Model
    ↓
Observations
    ↓
Candidate State
    ↓
Invariant
    ↓
Safe State Transition / Discard Rule
    ↓
Algorithm
    ↓
Correctness Argument
    ↓
Complexity Analysis
    ↓
Implementation
    ↓
Testing & Reconstruction
```

I care more about understanding **why an algorithm works** than memorizing a particular pattern.

## 🧩 Example Topics I'm Studying Deeply

### Priority Queue & Heap

```text
Priority Queue ADT
        ↓

```

---

### Monotonic Data Structures

For monotonic stack/deque problems, I focus on understanding:

```text
What are the candidates?

Why can a candidate be discarded?

Why can a discarded candidate never become useful again?

What invariant does the data structure maintain?
```

This makes the technique transferable instead of problem-specific.

---

### Graphs & Trees

I approach graph problems by reasoning about properties such as:

* connectivity
* paths
* cycles
* components
* traversal state
* structural invariants
* shortest-path relaxation
* tree properties

rather than immediately choosing BFS, DFS, or another algorithm.

## 📈 Progress Philosophy

I don't consider problem count alone a meaningful measure of progress.

A stronger signal is whether I can:

* solve the problem independently
* explain the core observation
* derive the invariant
* justify why discarded states are safe to remove
* prove correctness
* analyze complexity
* reconstruct the solution later without notes
* transfer the idea to a different problem

Therefore:

> **Transferable reasoning > pattern memorization > problem count.**
